# P1-06 — Форвардинг вебхука между контурами кредитует соседний

- **Severity:** 🟠 P1 (кросс-средовое начисление)
- **Area:** Платежи / инфра
- **Status:** OPEN

## Location
- `src/backend/index.js:50-51` — выбор `PEER_BACKEND_URL` (staging↔prod).
- `src/backend/index.js:54-90` — `forwardWebhookToPeer`.
- `src/backend/index.js:176-178` (Lava) и `:333-335` (crypto) — форвард при незаматченном заказе.
- Сети: `docker-compose.yml:74` / `.staging.yml:74` — общий внешний `n8n_internal`.

## Problem
Если заказ не найден локально, вебхук проксируется в соседний контур. Для крипто-канала (без подписи, см. P0-01) это значит: неподписанный/поддельный вебхук на стейдже уходит в prod-бэкенд по общей сети и начисляет реального пользователя, если заказ есть в prod.

## Attack / Failure vector
POST поддельного крипто-вебхука на staging-эндпоинт → форвард в prod → начисление prod-пользователю.

## Impact
Кросс-средовое начисление; усиление P0-01/P0-02.

## Suggested fix
- Не форвардить вебхуки, ведущие к начислению, между средами; либо требовать валидную подпись **до** форварда.
- Раздельные аккаунты провайдеров на среду убирают причину форварда.
