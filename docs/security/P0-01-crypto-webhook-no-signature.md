# P0-01 — Крипто-вебхук без проверки подписи, сумма из тела запроса

- **Severity:** 🔴 P0 (неаутентифицированное начисление средств)
- **Area:** Платежи / вебхуки (0xProcessing)
- **Status:** OPEN

## Location
- `src/backend/index.js:298-438` — обработчик `POST /webhook/crypto` (и `/webhook/staging/crypto`, `/staging/webhook/crypto`).
- `src/backend/index.js:313` — `amountUSD` берётся напрямую из тела запроса.
- `src/backend/index.js:374`, `:378` — `userService.addWalletBalance(order.userId, depositAmount)`.

## Problem
Обработчик крипто-вебхука не проверяет ни подпись, ни HMAC, ни IP-источник. Статус успеха и сумма (`amountUSD`) полностью контролируются отправителем запроса. Заказ ищется по `billingID` / `paymentId` / `address` — все они предсказуемы или наблюдаемы публично (on-chain адрес, предсказуемый orderId → см. P2-10).

## Attack / Failure vector
Неаутентифицированный POST:
```
POST /webhook/crypto
{ "billingID": "CRYPTO-20260914-1234567890", "status": "success", "amountUSD": 10000 }
```
→ заказ помечается оплаченным и на баланс пользователя зачисляется произвольная сумма. Атака масштабируется перебором orderId.

## Impact
Полная компрометация крипто-платежей: бесплатные пакеты и произвольное пополнение баланса без реальной оплаты.

## Suggested fix
- Проверять подпись 0xProcessing (HMAC-SHA256 по `SignatureKey`) в fail-closed режиме — при отсутствии/несовпадении отклонять `403`.
- НЕ доверять сумме из тела: начислять `order.amount` или подтверждённую on-chain сумму, привязанную к конкретной транзакции.
- В репозитории уже есть корректный обработчик с проверкой подписи — `src/backend/meemeeWebhooks.js:35-43,174-179`, но он **нигде не импортируется**. Подключить его или перенести проверку в `index.js`.
