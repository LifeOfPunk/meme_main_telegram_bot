# P1-05 — Общий `.env` между prod и staging

- **Severity:** 🟠 P1 (утечка секретов/сред, реальные списания на стейдже)
- **Area:** Инфра / разделение сред
- **Status:** OPEN

## Location
- `docker-compose.yml:21-22` и `docker-compose.staging.yml:21-22` — оба сервиса используют `env_file: .env`.
- `docker-compose.yml:46` — на prod-`admin` задан `STAGING_REDIS_URL`.
- `src/services/User.service.js:40-50`, `:80-95` — dual-write пользователя в staging-Redis.

## Problem
Prod и staging монтируют один и тот же `.env`, т.е. используют одинаковые ключи Lava/0xProcessing, `MERCHANT_ID` и webhook-секреты. Тестовые платежи на стейдже идут через реальный мерчант, а вебхуки двух контуров криптографически неотличимы. Дополнительно prod-`admin` дублирует пользователей в staging-Redis.

## Attack / Failure vector
- Тест на стейдже создаёт реальные платежи/списания.
- Секрет подписи один → подделка/переигровка вебхука валидна в обоих контурах (усиливает P0-02).
- Prod-данные затирают/подмешиваются в staging-Redis.

## Impact
Стирание границы сред: реальные деньги на стейдже, общий секрет, смешение пользовательских данных.

## Suggested fix
- Отдельный `.env` на среду; для стейджа — отдельный (тестовый) мерчант/ключи и **отдельный** webhook-секрет.
- Ограничить dual-write (по умолчанию выключить; включать только осознанно).
