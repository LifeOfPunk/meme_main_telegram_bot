# P0-04 — «Проверить оплату» зачисляет весь баланс адреса, а не сумму заказа

- **Severity:** 🔴 P0 (переначисление / чужие средства)
- **Area:** Платежи (ручная on-chain проверка)
- **Status:** OPEN

## Location
- `src/services/PaymentCrypto.service.js:301-308` — возвращает **текущий on-chain баланс адреса** (`amount: usdtBalance`).
- `src/services/PaymentCrypto.service.js:348-352` — то же для TRC-20 (Tron).
- `src/controllers/paymentController.js:636`, `:648` — зачисляет `result.amount` (весь баланс) на кошелёк.

## Problem
`checkPaymentStatus` считает платёж подтверждённым при балансе адреса `>= 0.5` и возвращает **весь баланс адреса**, а не сумму заказа. `handleCheckPayment` зачисляет это значение целиком.

## Attack / Failure vector
Если 0xProcessing переиспользует адреса депозитов или на адресе есть остаточные/агрегированные средства — пользователь получает на баланс всю сумму на адресе (в т.ч. чужой депозит), заплатив минимум.

## Impact
Переначисление сверх оплаченного; потенциально зачисление чужих средств.

## Suggested fix
- Зачислять строго `order.amount` (или сумму конкретной подтверждённой транзакции этого заказа), а on-chain использовать только как факт подтверждения.
- Гарантировать уникальный адрес на заказ или матчить по txid/сумме, а не по балансу адреса.
