# TASK-03: Фикс ошибки 400 оплаты картой (Lava API) + One-Click без ручного ввода Email

## 📌 Описание проблемы
1. При выборе «💳 Карта» и вводе реального Email (например, `cypress.rink@gmail.com`) бот падает с ошибкой:
   `❌ Ошибка создания платежа: AxiosError: Request failed with status code 400`
   Ссылка на оплату картой не создается, воронка покупки полностью заблокирована.
2. Необходимость ручного ввода Email снижает конверсию. Если платежный шлюз требует Email/телефон для отправки фискального чека, этот процесс должен быть максимально бесшовным (1-Click).

## 🔍 Причины ошибки 400
В сервисе `PaymentFiat.service.js` запрос на создание счета в Lava может падать из-за:
- Невалидного или устаревшего `offerIdLava` в `config.js` (например, оффер деактивирован в кабинете Lava).
- Неверного формата тела запроса (Lava API v1 / v2 изменения спецификации).
- Отсутствия обязательных заголовков или несоответствия секретного ключа `LAVA_SECRET_KEY` / `MERCHANT_ID`.

## 🛠️ План решения
1. Включить подробное логирование тела запроса и ответа ошибки 400 от Lava API для точной диагностики.
2. Актуализировать конфигурацию офферов (`PACKAGES` в `src/config.js`) и проверить подпись.
3. Проверить возможность передачи сгенерированного Email (или подтягивание Telegram-контакта) для устранения лишнего текстового диалога в боте.
4. Протестировать создание боевой платежной ссылки на стейдже.

## ✅ Критерии приемки (Definition of Done)
- [ ] Ошибка 400 устранена, при выборе карты формируется кликабельная ссылка на страницу оплаты картой.
- [ ] Шаг оплаты картой работает максимально бесшовно без лишних блокирующих запросов.
- [ ] После тестовой оплаты вебхук корректно начисляет пакет видео в Redis.
