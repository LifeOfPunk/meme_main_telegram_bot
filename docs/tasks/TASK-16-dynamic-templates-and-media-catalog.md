# TASK-16: Динамический каталог шаблонов и медиа-активов (Шаблонизатор мемов)

## 1. Контекст и бизнес-цель
Для масштабирования вирусных видео-шаблонов необходим единый реестр, позволяющий добавлять новые мемы без хардкода в кодовой базе Telegram-бота (`bot_start.js`) и прототипа.

Каждый шаблон включает 2 обязательных медиа-актива:
1. **Исходный видеоряд / ключевой кадр** (`video` / `preview_frame`).
2. **Скриншот вирусной статистики** (`statistic` с реальным числом просмотров, например, 1.1M+).

## 2. Архитектурная схема
- Конфигурации хранятся в `src/memes/*.json` и синкаются в единый `proto-media/templates.json`.
- `bot_start.js` формирует `replyWithMediaGroup` динамически на основе объекта `meme.media`, избавляясь от цепочки `if (memeId === 'mama_taxi') ... else if (memeId === '228')`.
- Веб-прототип рендерит кнопки каталога и модалы детального просмотра из этой же структуры.

## 3. Требования к данным шаблона (JSON Schema)
```json
{
  "id": "mama_taxi",
  "name": "🚕 Мама вызывай",
  "status": "active",
  "media": {
    "video": "./media/mother.MP4",
    "video_preview": "/proto-media/mother_frame.jpg",
    "statistic": "./media/statistic.jpeg",
    "statistic_preview": "/proto-media/statistic.jpeg",
    "views_count": 1136642,
    "views_badge": "🔥 1,136,642 просмотров"
  },
  "prompt": {
    "scene": "...",
    "visual": "...",
    "audio": {},
    "notes": "..."
  }
}
```

## 4. Acceptance Criteria
- [x] В `mama_taxi.json` и `228.json` добавлена секция `media` с путями к видео и скриншотам статистики.
- [x] В `bot_start.js` отправка медиа переведена на динамический цикл `meme.media` с проверкой существования файлов (`fs.existsSync`).
- [x] В интерактивном прототипе оба шаблона выводят 2-колоночную сетку Telegram с бейджем просмотров и возможностью зума.
- [ ] Готов механизм добавления новых шаблонов через конфигурационный файл без правок логики бота.
